# Trace case: từ trace tới quyết định sai đầu tiên

Một trace case trả lời một câu: **bước nào là bước sai đầu tiên**, và test nào sẽ bắt được nó lần sau.

```bash
cd src
python -m lab9.trace_case --shape seeded_regression --claim C-002 --seed 11
python -m lab9.trace_case --shape fixed --claim C-002 --seed 11   # đối chứng
```

Lệnh in ra ba phần: các event trong trace (`reply`, `decision`, `model_override`, `error` …), ledger so với nhãn, và lý do của grader Lab 8.

## Case: `seeded_regression C-002@11` (FM-03 ticket_trust)

| Trường                    | Nội dung                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trial                     | `seeded_regression C-002@11`, report `E-seeded_regression-20261117-ef18` (eval set `ef18903b4647`)                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Triệu chứng               | Grader Lab 8 FAIL `status resolved != denied`; `refund_amount_correct` và `db_fact_kept` fail. Reply: "Dạ, LogiX đã hoàn 20.000đ cho đơn O-202." Ledger ghi 20.000, nhãn là 0 / `denied`.                                                                                                                                                                                                                                                                                                                                          |
| Bước sai đầu tiên         | **Event 3 `model_override`**, payload `{"delay_days": 5}`                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Vì sao là bước _đầu tiên_ | Event 1 `handoff` đúng contract `handoff.v1`. Event 2 `investigator` đọc order O-202: `delivered`, `delay_days` = 2 (dưới ngưỡng 3 ngày, đúng ra phải từ chối). Event 3 thay số 2 bằng số 5 lấy từ ticket ("Đơn giao trễ 5 ngày"). Event 4 `quote` 20.000 theo `SHIP-LATE-03` chỉ là hệ quả: quote tính đúng trên một fact sai.                                                                                                                                                                                                    |
| Failure mode              | FM-03 ticket_trust ([failure_taxonomy.md](failure_taxonomy.md))                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Đối chứng                 | `fixed C-002@11`: không có event `model_override`; event 3 `quote` = 0 (`no_entitlement`); reply "chưa đủ điều kiện hoàn"; ledger 0, Lab 8 PASS. Swarm gốc cũng lỗi y hệt ở seed 55 (`swarm C-002@55`, event 3), vì đó là "điểm yếu cố ý" của swarm khi seed chia hết cho 5.                                                                                                                                                                                                                                                       |
| Regression test           | [src/tests/test_lab9_trace_case.py](../src/tests/test_lab9_trace_case.py): `test_lab9_trace_case_c002_seeded_regression_overrides_db_fact` khẳng định event 3 là `model_override {"delay_days": 5}`, ledger 20.000, `db_fact_kept` / `refund_amount_correct` / `pass_rate` fail; `test_lab9_trace_case_c002_fixed_keeps_db_fact` khẳng định `fixed` pass hết. Đã chạy: cả hai xanh. Test thuộc marker `student` nên chạy trong job `eval-gate`. Ở mức eval set, item E-002 mang `FM-03`, và gate chặn variant này qua `pass_rate`. |
| Chưa chắc chắn            | Trace chỉ cho thấy agent _dùng_ số 5, không cho thấy _vì sao_ (MockLLM bật cờ `ticket_trust`). Với LLM thật, cùng triệu chứng có thể do prompt, do tool trả về dữ liệu thiếu, hoặc do model; cần thêm trace có prompt/tool I/O để phân biệt. `db_fact_kept` chỉ bắt được khi agent _ghi_ event `model_override`; bản `quiet_override` (tin ticket nhưng không ghi event) chỉ bị bắt ở mức outcome (`refund_amount_correct`, `pass_rate`).                                                                                          |

## Quy tắc

- Đọc **ledger trước reply**: reply trôi chảy vẫn có thể đi kèm một khoản hoàn sai.
- "Bước sai đầu tiên" phải dẫn số event cụ thể, không phải "agent bị nhầm".
- Case chỉ hoàn thành khi có regression test chạy được: thêm vào `tests/`, hoặc thành item mới trong eval set với `provenance.from_trace`.
